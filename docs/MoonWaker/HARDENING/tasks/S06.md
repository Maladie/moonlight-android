# S06 — Complete coherent observation from producer to UI and decisions

## Integrated outcome
Running stream, game tiles and transition readiness agree on one coherent, versioned projection without reconnecting a live stream due to game uncertainty. Every uncertain observation converges within a bounded time to resolved state or an explicit recovery path; after recovery, the next authorized Play is not indefinitely blocked.

## Entry gate
Do not mutate S06 production code until S05 has required physical Windows/TV acceptance and its exact accepted sources, artifacts and evidence are frozen as the S06 input fingerprint. `CODE_VERIFIED_DEVICE_PENDING` for S05 blocks S06 mutation. Planning, characterization and the required independent design review may proceed without claiming S06 has started.

## Required work
Independently review the producer's atomic/serialized boundary, identities, epoch/revision and smallest authorized protocol extension before editing. A single Gateway endpoint wrapping incoherent Bridge reads is not atomic.
Define the observation protocol before implementation. The coherent producer snapshot must carry a schema version, producer boot identity, monotonic revision within that boot, observation time/freshness, actor and execution scope, provider state, canonical game identity, verified process identity, window/readiness evidence and reason, and the relevant operation/transition/generation correlation. Represent missing evidence explicitly; do not collapse the contract to one `ready` boolean.
Publish game/process/window/readiness under one producer serialization boundary and revision. Keep the local retained socket and its generation as a separate observation axis. Preserve child response scope and use the same lifecycle projection as the parent, with no parent-only health dependency.
Apply this truth hierarchy: the retained-session owner is authoritative for this client's local transport; the Game Provider is authoritative for coherent game/process/window evidence; Gateway is authoritative for authentication, scope and correlation; SessionStateResolver is the single Android projection consumed by presentation and decisions. No Activity may reconstruct an alternative truth from individual fields.
Define bounded liveness for every `UNKNOWN`/uncertain state. Each stage has an explicit deadline and must converge to `READY`, `IDLE`, `RECOVERY_REQUIRED` or `UNAVAILABLE`; it must not keep Play blocked forever. The recovery action must clear or replace only correctly fenced state, and its success or failure must be followed by a tested next authorized Play attempt.
In the SAME task migrate Gateway consumers, transition observation, SessionStateResolver, host badges, tiles and start/resume/retain decisions. Remove competing decisions from Game/ConsoleActivity; reuse canonical owners rather than new caches. A known live transport survives unknown/mismatched game identity. Unknown is not idle; a remote client's stream is not our local ready stream. Readiness may reveal or advance only evidence matching the expected boot/revision, game and transition/generation.
Retain compatible old response handling only where it is safe, documented and tested; reject unsafe combinations before effects. Do not ship a dormant endpoint or half-migrated product milestone.

## Required architecture outcome
Extract coherent snapshot production from provider HTTP handling; centralize projection/observation through existing resolver/coordinator owners; remove parallel host/tile/start decisions from ConsoleActivity and Game.

## Required implementation sequence
Characterize current production callers and failure behavior; freeze the protocol and compatibility matrix; implement the producer boundary; expose the scoped Gateway response; add one Android parser/projection; migrate every consumer; delete obsolete decisions; then run independent behavioral and architecture review. Internal passes may be incomplete only within the unaccepted candidate.

## Required regressions
Use controlled clocks/latches/queues rather than sleeps. Cover at least:

- state mutation between formerly separate reads, producer restart/revision reset, and delayed observation A arriving after B;
- local live transport with unknown/mismatched game, Gateway offline, and a remote client's stream;
- child scope without parent health, another TV/execution scope, partial or unavailable emulator inventory, and safe old/new protocol combinations;
- repeated game switches, including an emulator-backed title, with badge, tile, Play decision, transport continuity and privacy cover asserted from the same projection;
- every timeout/error terminal: perform the offered recovery, then prove the next authorized Play succeeds within the declared bound.

Diagnostics and saved evidence must include schema version, producer boot/revision, observation age and provenance, local transport generation, expected/received game identity, rejection/recovery reason and final UI projection so a mixed or stale decision is attributable.

## Non-goals
No unrelated rewrite, generic framework, duplicate authoritative state, source-only behavioral proof, production debug bypass or unauthorized deployment. S06 does not redesign S05 termination/hard-reset semantics, repair external emulator configuration or implement S07 transport ownership, S08 launch preflight/warm-up or S09 frame-commit privacy; it must still avoid worsening them and must integrate safely with their existing contracts. Later slices may improve separate existing defects but must not complete this slice's introduced half-working behavior.
