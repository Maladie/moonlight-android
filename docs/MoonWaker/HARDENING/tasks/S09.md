# S09 — Integrate reliable artwork barriers and presentation handoffs

## Integrated outcome
Artwork handoffs always resolve, reject stale reveals and retain transport on game-only stop/switch.

## Required work
Extract one narrow artwork/cover handoff barrier from Activities with explicit submitted/cancelled/unavailable outcome exactly once. Fence callback by transition and surface identity; move state and all callers, remove doAfterNextFrame-style dropped paths.
Use supported render APIs for actual target API/renderer. A frame-commit callback is not proof of physical screen visibility; do not equate two animation callbacks with correct presentation. LaunchTransitionController remains canonical target-readiness/fresh-frame/input gate.
A→B uses artwork B; stop-only may open carousel promptly with truthful stopping state and the same transport. Full quit/child expiry cannot depend on rendering availability. Parent manual reveal remains recovery, never a child-limit bypass. Check overlay and pad shortcut equivalence plus hidden input isolation.
Automate detach/cancel/late frame/no-surface/repeated commands and targeted real-device switches. Lab evidence includes actual new-game frames, artwork/desktop exposure, counters and input probe; do not accept blanket delayed reveal as the fix.

## Additional required rules
- Every barrier has a bounded deadline that produces an explicit UNAVAILABLE outcome exactly once; never a stuck cover or black screen.
- Proof of a fresh frame for a new generation comes from the decoder's rendered-frame signal (MediaCodec.OnFrameRenderedListener or the existing fresh-frame gate in LaunchTransitionController), not from view/animation callbacks.

## Loading-view presentation (from UI/UX audit UX-03, UX-10)
The barrier work touches ConsoleStreamLoadingView, so these defects are fixed here rather than in a parallel UX change:
- `stepsView` is created and toggled VISIBLE but never added to the view hierarchy; attach it so the stage list is actually shown.
- One stable information layer in both artwork and non-artwork modes: game title, current real stage (from the S08 typed preparation/connect status, never a rotating decorative message), elapsed time and the available action (cancel/retry/explicit reveal). The stage text has more typographic weight than decorative messages.
- `decodeSplashArtwork` runs synchronously; decode off the UI thread and deliver the bitmap fenced by transition identity, so a late decode never paints over a newer transition and a slow decode never delays the barrier outcome.
- Unconfirmed host termination shows an honest state (TV disconnected; the computer did not confirm the session ended) with a "Check again" action that queries the host; it never restores stale local ownership and never delays the unconditional local stop.
